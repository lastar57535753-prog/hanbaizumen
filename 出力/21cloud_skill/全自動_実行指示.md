# 21Cloud 全自動登録 実行指示（PCのClaude Code用）

依頼者の指示：
- 15マンション・17住戸を、21Cloud 経由ですべてアットホームに掲載する
- 途中で依頼者に確認せず、全件を最後まで進める
- 写真はできるだけ多く入れる（同一住戸の他社掲載写真は許可済み。透かし入りは使わない）
- コメントは富裕層向けに、シンプルで的確に書く

## 0. 最初に読むもの
1. `出力/21cloud_skill/SKILL.md` と `出力/21cloud_skill/form-fields.md`
   - スキル 21cloud-bukken-touroku と同じ内容。技術的な扱い方はこれに従う。
   - ただし、「登録・出稿」ボタンについては下の3章が優先する。
2. 各住戸の `出力/NN_マンション名/【住戸】/21cloud入力.json`（正）と `21cloud入力.md`
3. `出力/図面基準データ.md`
   - 販売図面の読み取り結果で、数値の最終的な照合先になる。

## 1. 使う道具（主はPlaywright。どちらも動作確認済み：模擬画面で入力・写真アップロード・ボタン押下を検証）
- **主ルート：Playwright でChromeを直接操作する**
  - 依頼者が、デバッグポート付きのChrome（`21cloud_PC全自動手順.md` の手順2）を起動し、そのChromeで21Cloudにログインしておく。
  - 使うスクリプトは `出力/21cloud_skill/c21.py`。
    - `python 出力/21cloud_skill/c21.py shot 名前`：画面をPNGに保存する。Readで開いて画面を確認する。
    - `python 出力/21cloud_skill/c21.py fields [絞込語]`：入力欄の一覧（id・name・ラベル・現在値・maxlength）を出す。**最初の1件目で必ず実行して、画面の項目と json の basic の対応表を作る。**
      - 対応表は `出力/21cloud_skill/項目対応表.json`（`{"価格": "#kakakuF", ...}`）に保存し、2件目以降は使い回す。
    - `python 出力/21cloud_skill/c21.py set '{"#id":"値", ...}'`（jsonファイルのパスも可）：まとめて入力する。
      - select にはラベル文字でも入れられる。checkbox には true、radio には "ON" を渡す。
      - **Windows（PowerShell）では、JSONをコマンドライン引数に直接書くと引用符が壊れる。** 必ず一時ファイル（例：`c21_shots/set.json`）に書き、そのパスを渡すこと。
    - `python 出力/21cloud_skill/c21.py comments <21cloud入力.json>`：キャッチコピー登録モーダルに17コメントを入れる。
    - `python 出力/21cloud_skill/c21.py click "テキスト"`：ボタンやリンクを押す。確認ダイアログは自動でOKになる。
    - `python 出力/21cloud_skill/c21.py read '#id' ...`：保存後に値を読み出して照合する。
  - 写真は `出力/21cloud_skill/upload_photos.py`。
    - まず `--discover` でスロットの構造を確認する。
    - 次に `upload_photos.py <json> --save` を実行する。images を順に、アップロード・カテゴリ・コメント・「画像登録完了」まで行う。
    - 写真は `upload_file`（`21cloud_upload/` 内の、長辺2560px以下に最適化した掲載順のファイル）を使う。
- **補助ルート：Claude in Chrome**（`claude --chrome`）
  - Playwright でうまくいかない画面だけに使う。例：画像がcanvas描画で、ファイル入力が見つからない場合。
  - `21cloud_コメント貼付.js` は javascript_tool でそのまま実行できる。
- ログイン画面が出たら、そこでだけ止まり、依頼者にログインを頼む。ログインは代行しない。
- どちらのルートでも写真を入れられない場合は、写真以外をすべて入力し、写真の欄は「写真待ち」とログに残して次へ進む。

## 2. 住戸ごとの手順（No.01-46・47階 → No.15 の順。1件のエラーで全体を止めない）
1. 物件登録画面で、「マンション」列の「通常登録」を押す。
2. **基本項目**：json の `basic` を画面の各項目に入れる。
   - 項目名が画面と完全に一致しない場合は、意味の合う欄に入れる。
   - `確度` が「未確認」の項目は空欄のままにする。
   - 必須項目が空欄になる場合：数値項目なら `hold` 扱いにして一時保存で止める。選択肢や文言の項目なら、根拠のある最も近い値を入れ、ログに記録する。
3. **設備・特徴**：json の `features` にあるものだけチェックする。根拠のないものはチェックしない。
4. 必須項目の残り（「必須残:N項目」の表示）が0であることを確認する。
5. **キャッチコピー・コメント**
   - キャッチコピー登録モーダルを開き、`c21.py comments <json>` を実行する。補助ルートでは、同じフォルダの `21cloud_コメント貼付.js` を javascript_tool で実行する。
   - 返ってきた文字数に `NOT FOUND` や上限超えがないことを確認して保存する。
   - 禁止文言のダイアログが出たら、「いいえ」を押して言い換え、再保存する。言い換えた文言はログに残す。
6. **画像**
   - `upload_photos.py <json> --discover` の後、`upload_photos.py <json>` を実行する。json の `images` を order の順にアップロードする。
   - 各スロットに `category`（1スロット目のselect）と `comment20`／`comment100` を入れる。
   - 外観と間取図に専用スロットがあれば、そちらに入れる。
   - 入れた後、オーバーレイ手法（SKILL.md参照）でサムネイルを目で見て、カテゴリとコメントが写真の中身に合っているか確認する。
   - 空いているスロットにカテゴリやコメントが残っていたら消してから、「画像登録完了」を押す。
   - **`images_pending_permission` の写真は入れない。** 同一住戸以外の他社掲載や分譲会社サイトの写真で、転載許可を確認していないため。
   - 透かし（元付・他社のロゴ）の入った写真は使わない（依頼者指示 2026-09-28）。`images` には透かしが無いことを目視で確認した写真だけが入っている。
7. **保存後の照合**（毎件必ず行う）
   - 保存後に画面の値を読み直し、次の項目が json・図面基準データ.md と一致しているか確かめる。
     - 価格、専有面積、所在階・階建、間取り、管理費、修繕積立金、その他費用、築年月、総戸数、交通、現況、引渡
   - 違っていたら直して、もう一度照合する。一致するまで繰り返す。
8. **出稿判断**（下の3章）

## 3. 「登録・出稿」を押す条件（依頼者指示：数値の食い違いは販売図面の値で入力し、登録まで進める）
- 情報源の間で数値が食い違っている項目（価格・面積・所在階・費用・築年月・駅徒歩など）は、**販売図面の値**を入力する。
  - 販売図面の値は、図面基準データ.md とjsonの basic で「確度＝図面」になっているもの。
  - 入力したうえで、**「登録・出稿」まで進める**。
  - 依頼者の了承があるので、確認なしで押してよい。
- 押す前に、手順7の照合で次を確かめる。
  - 画面の値が販売図面の値と一致していること
  - 図面にない数値は、jsonの値（出典付き）または空欄になっていること
- 一時保存で止めるのは、次の場合だけ。止めた理由はログに書く。
  - 必須項目の数値が、販売図面にもjsonにもない。
  - システムのエラーで保存できない。
- 数値以外の hold（向きの表記ゆれ、設備名など）は、確実な表現だけで入力し、そのまま出稿する。
- 食い違いがあった項目は、出稿後にログの「照合結果」欄に「図面値で入力（他の値：○○）」と残す。

## 4. ログ（毎件更新）
`出力/21cloud登録ログ.md` に、1住戸につき1行追記する。
- 追記する内容：
  - No／マンション／住戸
  - 状態（出稿済／一時保存（理由）／写真待ち／エラー）
  - 21Cloudの物件番号
  - 画像枚数
  - 照合結果
  - 言い換えた禁止文言
  - 日時
- 全件が終わったら、最後に次をまとめる。
  - 出稿した件数と一時保存にした件数
  - 依頼者が対応すること（hold の中身と、写真の許可確認）
- 終わったら `git add -A && git commit -m "21Cloud登録ログ" && git push` を行う。
  - push できない場合は、ローカルに残すだけでよい。

## 5. 注意
- 数値は推測で入れない。json に値がない数値項目は空欄にする。
- コメントを自分で書き直すときも、form-fields.md の文字数上限と禁止文言を守る。
  - at homeおすすめコメントには半角文字を使わない。
  - 仲介手数料には触れない。
- 取引態様は、自社（ラスターハウス）の立場で選ぶ（通常は「仲介」）。
  - 元付業者の情報は、社内向けの欄に入れる。
- 同じ物件がすでに21Cloudに登録されていないか、物件検索で確認してから新規登録する。
  - すでにあれば新規には作らず、その物件を更新する。
